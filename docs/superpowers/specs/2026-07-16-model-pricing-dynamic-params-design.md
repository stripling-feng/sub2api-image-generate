# 图片模型定价与动态参数设计

## 目标

- 图片模型后台只维护服务商、模型标识、接口路径、单张美元售价和启用状态。
- 管理员不再编辑参数 JSON、最大张数或参考图上限。
- 工作台从后端获取模型配置，并按沧元算力文档动态展示画幅、质量、自定义尺寸和生成数量。
- 实际计费由当前模型单价乘以生成张数，不再使用全局固定价格。
- `frontend` 和 `client` 的开发代理统一指向 `http://localhost:10102`。

## 数据结构

在 `ai_models` 增加：

```sql
unit_price_usd numeric(20, 10) not null default 0.5
```

价格必须大于或等于零。现有模型回填为 `0.5`，之后由管理员按业务售价调整。

现有 `parameter_schema`、`default_params`、`max_count` 和 `max_reference_images` 字段暂时保留，避免破坏现有数据和接口。后台表单不再暴露这些字段；它们由数据库迁移中的模型文档配置统一维护。

## 后台管理

图片模型新增和编辑保留：

- 模型服务商
- 模型标识
- 显示名称
- 上游模型
- 生成路径
- 编辑路径
- 单张价格（USD）
- 异步模式
- 支持蒙版
- 状态
- 排序

删除以下可编辑项：

- 参数配置 JSON
- 默认参数 JSON
- 最大张数
- 参考图上限

模型列表增加“单价”列，格式为 `$0.50 / 张`。

## 文档参数配置

参数配置以沧元算力公开价格与模型文档接口为依据，固化到后端数据库迁移，不在运行时依赖外部文档站点。

### gpt-image-2

- 画幅：`1:1`、`3:2`、`2:3`、`auto`
- 不显示质量和自定义尺寸
- 单次生成数量：1–10
- 不支持蒙版

### gpt-image-2-1k / 2k / 4k

- 画幅：`1:1`、`5:4`、`7:6`、`9:16`、`21:9`、`16:9`、`3:2`、`4:3`、`4:5`、`3:4`、`2:3`
- 支持符合文档约束的自定义尺寸
- 质量：`low`、`medium`、`high`，默认 `medium`
- 单次生成数量固定为 1
- 支持参考图和蒙版，参考图安全上限固定为 9

所有模型仍执行全局安全上限：单次最多 10 张、最多 9 张参考图、单文件最大 10 MB。

## 模型接口与工作台

`GET /api/images/models` 为工作台唯一模型配置来源，在现有响应中增加：

- `unitPriceUsd`
- 文档定义的 `parameters`
- 文档定义的数量限制
- 蒙版和参考图能力

工作台加载模型后：

1. 根据 `parameters` 自动展示画幅、质量和自定义尺寸控件。
2. 根据模型数量限制控制生成张数。
3. 根据 `unitPriceUsd × count` 显示预计扣费。
4. 提交时只发送当前模型允许的参数。

不新增第二套模型配置接口，也不让客户端自行决定模型能力。

## 计费流程

创建任务时从数据库读取模型单价：

```text
冻结金额 = unitPriceUsd × count
```

冻结、成功结算、失败释放和异步轮询结算继续复用现有 sub2api 计费流程。任务已经保存 `billingAmount`，因此任务创建后的价格变更不会影响已创建任务。

价格使用 `BigDecimal` 计算并保留现有 10 位小数精度。前端显示两位小数，但不参与最终计费。

## 校验与错误处理

- 后台拒绝负数、空值或非数字价格。
- 后端拒绝超出当前模型文档限制的数量、尺寸、画幅和质量。
- 未配置、停用或售价无效的模型不允许创建任务。
- 工作台拿不到模型配置时显示“没有可用的图片模型”，不使用本地兜底价格。
- 计费失败继续使用现有任务账单状态记录并执行释放或补偿。

## 开发代理

- `frontend/vite.config.js` 的所有后端代理目标改为 `http://localhost:10102`。
- `client/vite.config.ts` 的默认 `VITE_API_PROXY` 改为 `http://localhost:10102`，仍允许环境变量覆盖。

## 验证

- 数据库迁移验证售价字段、默认值和非负约束。
- 后端验证不同模型的参数输出和参数拒绝逻辑。
- 计费测试覆盖单张、多张、失败释放及任务创建后修改售价。
- 工作台验证四个模型切换后的动态控件、数量限制和预计扣费。
- 管理后台验证售价新增、编辑、列表显示和非法价格提示。
- `frontend`、`client` 分别执行生产构建。
